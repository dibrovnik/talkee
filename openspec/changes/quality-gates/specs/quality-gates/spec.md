# Spec Delta

## Purpose

Определяет обязательные автоматические проверки качества talkee, одну команду для их запуска и места, где они выполняются (git-хуки и CI), чтобы некачественный код не попадал в репозиторий.

## ADDED Requirements

### Requirement: Single gate command
Репозиторий SHALL предоставлять команду `bun run gate`, которая выполняет все обязательные проверки и завершается с кодом 0 только если все они прошли. Обязательные проверки:
- синхронность версий и наличие записи в CHANGELOG;
- сетевой allowlist;
- отсутствие старого имени;
- актуальность путей в `AGENTS.md`;
- гигиена git-индекса;
- валидность OpenSpec (`--strict`);
- форматирование и линт TS/JS;
- форматирование Rust;
- проверка типов TS для кода и тестов;
- clippy без предупреждений;
- все TS-тесты;
- все Rust-тесты workspace.

#### Scenario: Всё в порядке
- **WHEN** разработчик запускает `bun run gate` на чистом актуальном дереве
- **THEN** все проверки выполняются по очереди, по каждой печатается статус, и команда завершается с кодом 0

#### Scenario: Упал один тест
- **WHEN** один Rust-тест падает
- **THEN** `bun run gate` завершается с ненулевым кодом и в итоговой сводке показывает, какая проверка упала

### Requirement: Fast fail ordering
`bun run gate` SHALL запускать проверки в порядке возрастания стоимости: статические скрипты → форматирование → типы/линт → тесты. Команда MUST останавливаться на первой упавшей группе, если не передан флаг `--keep-going`.

#### Scenario: Ошибка форматирования
- **WHEN** в файле `.tsx` нарушено форматирование
- **THEN** `bun run gate` завершается на группе форматирования, не запуская тесты

### Requirement: Pre-commit hook
При `git commit` SHALL автоматически запускаться быстрая проверка изменённых файлов: форматирование и линт изменённых TS/JS/JSON-файлов, `rustfmt --check` для изменённых `.rs`, проверка версий и имени. Хук MUST выполняться менее чем за 10 секунд на типичном коммите.

#### Scenario: Неотформатированный Rust-файл
- **WHEN** разработчик коммитит `.rs` файл с нарушением форматирования
- **THEN** коммит отклоняется с сообщением, какую команду запустить (`cargo fmt`)

### Requirement: Pre-push hook
При `git push` SHALL автоматически запускаться `bun run gate`.

#### Scenario: Push с падающим тестом
- **WHEN** разработчик выполняет `git push` при падающем TS-тесте
- **THEN** push отменяется

### Requirement: CI runs the gate
CI SHALL запускать `bun run gate` и сборку фронтенда (`bun run build`) на каждый push в `main` и каждый pull request на macOS runner'е.

#### Scenario: Pull request с нарушением линта
- **WHEN** в pull request есть нарушение правила Biome
- **THEN** CI-проверка помечается как failed

### Requirement: No blanket suppressions
Подавление правил линтера SHALL быть точечным (конкретное правило на конкретной строке или в конкретном файле) и сопровождаться комментарием с причиной. Глобальное отключение правила MUST быть перечислено в конфигурации с комментарием с причиной.

#### Scenario: Проверка подавлений
- **WHEN** в коде есть `// biome-ignore` или `#[allow(clippy::...)]` без пояснения
- **THEN** ревью изменения (ручное или агентом) отклоняет его; Biome MUST требовать пояснение у `biome-ignore` (это его стандартное поведение)
