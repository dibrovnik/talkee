# Spec Delta

## MODIFIED Requirements

### Requirement: No background network traffic
Приложение MUST NOT выполнять сетевые запросы, которые не инициированы явным действием пользователя и не адресованы настроенному пользователем endpoint'у. Сюда относятся проверки обновлений, загрузка шрифтов, аналитика, crash-репорты, «пинги» и запросы профиля. Периодический анализ словаря SHALL обращаться только к выбранному текстовому backend после отдельного включения расписания и действующего согласия на передачу исторических фрагментов в API.

#### Scenario: Запуск без действий пользователя
- **WHEN** пользователь запускает приложение с выключенным расписанием словаря и ничего не делает 10 минут
- **THEN** приложение не открывает ни одного исходящего соединения, кроме соединений с `127.0.0.1`/`localhost` для управляемых локальных sidecar-процессов

#### Scenario: Открытие настроек
- **WHEN** пользователь открывает окно настроек
- **THEN** не выполняется ни проверка обновлений, ни загрузка удалённых шрифтов, стилей или изображений; открытие раздела «Словарь» само по себе не начинает анализ

#### Scenario: Явно настроенный анализ
- **WHEN** пользователь заранее включил расписание и подтвердил передачу истории выбранному API backend
- **THEN** допустим только ограниченный проход по правилам расписания; другие фоновые сетевые действия не разрешаются

## ADDED Requirements

### Requirement: Separate historical-text consent
Перед первым анализом через удалённую LLM приложение SHALL показывать получателя, модель, область и примерный объём исторических данных. Ручной запуск и расписание MUST иметь отдельные явные подтверждения; существующее согласие на текущую очистку MUST NOT автоматически разрешать анализ истории.

#### Scenario: Первый API-анализ
- **WHEN** пользователь нажимает «Проанализировать историю…» при настроенном API
- **THEN** до отправки показано, что выбранные фрагменты диктовок будут переданы этому провайдеру; отмена диалога не отправляет запрос

### Requirement: Backend-bound revocable analysis authorization
Согласие SHALL относиться к конкретному типу backend, нормализованному адресу и модели. Смена API backend или модели MUST приостанавливать автоматический анализ до нового согласия; отзыв MUST отменять текущий проход и запрещать сохранение позднего ответа.

#### Scenario: Смена получателя
- **WHEN** ранее разрешённый DeepSeek endpoint заменён другим удалённым endpoint
- **THEN** история не отправляется автоматически новому получателю, показано действие подтверждения новой настройки

### Requirement: Data minimization and local diagnostic privacy
Анализ SHALL передавать только выбранные ограниченные текстовые фрагменты и непрозрачные ссылки для проверки доказательств. Он MUST NOT добавлять аудио, summary, метаданные путей/приложений, статистику, другие источники истории и API-ключи в содержимое запроса. Логи MUST содержать только идентификаторы, количества, времена, безопасный endpoint и коды исходов, без словарных терминов и текста.

#### Scenario: Локальный анализ
- **WHEN** выбран управляемый локальный текстовый backend
- **THEN** все операции анализа и отмены остаются на loopback; удалённого fallback нет

### Requirement: History deletion removes derived evidence
Удаление записи или очистка истории SHALL удалять связанные цитаты, человеческие примеры, ссылки и прогресс анализа и пересчитывать производные предложения. Уже утверждённые термины MUST оставаться как самостоятельная настройка с явным объяснением; пользователь MUST иметь отдельное действие полного удаления данных персонализации.

#### Scenario: Очистка всей истории
- **WHEN** пользователь очищает историю во время анализа
- **THEN** проход отменяется, цитаты/примеры/предложения и курсоры удаляются, поздний ответ не возвращает данные, утверждённый словарь остаётся

### Requirement: No external-editor surveillance
Talkee MUST NOT наблюдать за содержимым редакторов, приложений или буфера обмена в фоне для поиска исправлений. Чтение исправленного текста SHALL выполняться только действием пользователя; отмена формы MUST удалять несохранённый захват.

#### Scenario: Пользователь редактирует вставленный текст
- **WHEN** пользователь правит текст во внешнем приложении и не вызывает «Запомнить исправление»
- **THEN** Talkee не читает эти правки и не создаёт пример незаметно
