# Design

## Context
getCurrentWindow() возвращает новый Window. Зависимые эффекты восстановления позиции и подписки запускаются на каждом рендере. set_widget_presentation публикует новый объект якоря, замыкая цикл.

## Goals / Non-Goals
Устранить постоянные IPC и рендеры в простое. Не отключать функции, прогрев STT или watchdog. Не оптимизировать несвязанные пайплайны без измерений.

## Decisions
В src/windows/widget/hooks/useWidgetController.ts хранить Window через useState(getCurrentWindow): один объект на экземпляр хука, без нового хелпера.
В src/windows/widget/hooks/useWidgetController.test.ts проверить lazy-инициализацию и отсутствие прямого вызова при рендере.

## Risks / Trade-offs
Проверка структуры исходника дополняется реальным замером release-процесса; она не заменяет runtime-проверку.
Повторное применение режима по SETTINGS_UPDATED_EVENT в Widget.tsx сохраняется.

## Migration Plan
Собрать подписанный release, проверить CPU, заменить установленное приложение с резервной копией.

## Open Questions
Нет.

- После: открытые настройки 1.581% суммарно за 60.09с; закрытые настройки, видимый остров 1.531% за 60.05с. Включён прогретый STT runtime.
- Профиль после исправления: основной поток Talkee ожидает события в CFRunLoop вместо непрерывной обработки IPC. Закрытие настроек сохраняет виджет.
- `bun run gate` прошёл полностью, включая clippy и Rust-тесты.
- Установлено в /Applications/Talkee.app; предыдущая сборка сохранена в /tmp/Talkee-before-cpu-fix-20261001.app.
