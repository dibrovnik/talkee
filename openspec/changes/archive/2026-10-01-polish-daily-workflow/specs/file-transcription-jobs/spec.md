# Spec Delta

## Purpose

Определяет устойчивую обработку загруженных аудио и видео внутри запущенного приложения, восстановление отображения задачи после навигации и честную приблизительную оценку остатка времени.

## ADDED Requirements

### Requirement: File jobs survive view changes
Запущенная файловая задача SHALL продолжаться при переключении вкладок, закрытии окна настроек и его повторном открытии, пока приложение работает. При возвращении пользователь MUST видеть ту же задачу, её последний прогресс или результат без повторного запуска. История SHALL отражать начало и конечный статус задачи, включая ошибку; входной путь MUST сохраняться для явного повтора. Полный выход из приложения не требует автоматического возобновления.

#### Scenario: Навигация и скрытие окна
- **WHEN** во время обработки длинного MP4 пользователь меняет вкладку, закрывает окно и затем снова открывает файлы
- **THEN** обработка не прерывается, отображается та же задача и текущий статус, после завершения результат появляется ровно один раз

#### Scenario: Параллельные попытки запуска
- **WHEN** запрос запуска повторно доставлен либо пользователь загружает второй файл при занятой обработке
- **THEN** дубликат не создаётся, новый отдельный файл явно ожидает своей очереди и не запускает вторую тяжёлую локальную обработку одновременно

### Requirement: Honest progress and remaining time
Интерфейс SHALL показывать этапы подготовки, распознавания, разделения говорящих и сборки, прошедшее время и приблизительное оставшееся время после появления достаточных измерений. Прогресс MUST основываться на завершённой обработке, а не на номере начатого фрагмента; 100% MUST появляться только после готового результата. При отсутствии данных SHALL отображаться «Оцениваем время», а не выдуманный таймер. Оценка MUST быть помечена как приблизительная и уточняться при изменении скорости.

#### Scenario: Первые фрагменты
- **WHEN** первый фрагмент ещё обрабатывается
- **THEN** интерфейс не считает его завершённым и показывает отсутствие надёжной оценки остатка

#### Scenario: Длинный файл
- **WHEN** завершены несколько фрагментов с известной длительностью
- **THEN** пользователь видит обработанную длительность, прогресс и приблизительный остаток по измеренной скорости

#### Scenario: Неизвестная длительность этапа
- **WHEN** началась подготовка или диаризация без данных для оценки
- **THEN** виден текущий этап и прошедшее время, точный ETA всего задания не заявляется

### Requirement: Safe long processing and usable results
Длинные файлы SHALL обрабатываться по нативному пути с существующими лимитами и чанкингом, без загрузки всего видео в память интерфейса. Закрытие окна MUST NOT означать отмену. Явная отмена и сбой MUST приводить к понятному конечному статусу без применения позднего результата; сохранённый текст MUST NOT теряться. Транскрипт SHALL иметь читаемое представление, копирование и временные метки/говорящих при наличии соответствующих данных.

#### Scenario: Большой видеофайл
- **WHEN** пользователь выбирает поддерживаемый видеофайл в пределах лимита
- **THEN** файл передаётся по пути, преобразуется нативно и распознаётся фрагментами, прогресс не зависит от видимости окна

#### Scenario: Явная отмена или сбой
- **WHEN** пользователь отменяет задачу либо один из этапов завершается ошибкой
- **THEN** состояние становится прерванным либо ошибочным, повтор доступен при наличии исходного файла, поздний ответ не превращает отменённую задачу в успешную

#### Scenario: Потоковый Nemotron
- **WHEN** файл обрабатывается Nemotron в режиме без диаризации
- **THEN** поддерживаемый потоковый путь сохраняется, новые возможности интерфейса не переводят модель скрыто на другую модель или endpoint
